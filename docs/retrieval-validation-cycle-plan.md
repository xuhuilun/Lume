## 探测后的视觉方案与过程核查

同权重开发探测发现：单纯强化“目标卡片内部”仍误读左右；结构化目标区域/点坐标能给出右端，但颜色仍把橙色叫红色。推荐一次调用的像素绑定方案：先用已有Pillow提取高饱和连通色块（缩图上最多16个、有尺寸/形状边界），模型在看原图时选择组件区域与候选标记，程序以该区域为参照计算位置，并由色块像素均值映射基础色名。目标区域内需仅有唯一候选、选定标记实际在区域内；不确定/歧义/坏几何不生成语义事实。模型保留general分支回答其他图像文字/数值。没有额外视觉调用、新依赖或给定正确颜色/坐标；这种几何/色相规则有适用范围，不证明模型一定选对语义目标。

过程核查新增明确语义：允许按原文阶段区分早期未执行建议与最终验证，status不是要求每一条消息都验证通过；原因解释可复述已记录故障/修订依据，不得补出未记载的深层根因。开发重放中的完整过程材料通过，字段/文件上限/环境反例仍拒绝。实现与完整复测后再记录效果，不把探测算成正式质量结论。Ollama规则拟升v6、Demo保持v2，确保旧任务不静默采用新视觉/核查协议。
