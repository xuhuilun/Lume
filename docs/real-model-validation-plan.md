## 目标与边界

沿用既有Python/FastAPI/PostgreSQL和OllamaProvider，不新增模型服务框架。验证embeddinggemma、qwen3:4b、qwen2.5vl:3b的实际推理，以及消息接入、派生、检索、工具决策、引用发布的完整链路。使用明确标注的人工合成资料，独立数据库或随机schema，禁止导入私人聊天。

单次联调只证明列出样例的可执行性；不能用于声称准确率、检索效果提升、生产性能或真实QQ接入通过。模型标签之外记录实际digest、量化、向量维数、服务版本、配置与执行时间。保留首次失败，修复后独立记录。

## 顺序

1. 核查适配器、模型官方接口、硬件及服务现状；在feature/real-model-validation分支完成后续开发。
2. 启动仅监听本机的Ollama验证实例，限制单模型加载和单请求并发。优先复用已存在权重，缺失时下载现有配置指定模型，记录下载失败与模型身份。
3. 建立可重跑的验证入口：分别验证真实向量、合法结构化动作、合成图片可见细节；完整调用现有Processor、search、Runner与答案读取链路。输出仅包含合成输入、公开运行配置和结果，不包含令牌、连接密码或内部思维文本。
4. 对真实调用暴露的错误作最小修复，补充与错误相关的回归，执行静态检查、数据库集成与真实模型复测。不得为了得到通过结果放宽引用、资格、版本或预算约束。
5. 保存原始机器可读记录与人工核对说明；完善运行文档。自检后提交、合并main并推送指定Lume远端；输出归档放工作区outputs目录。
6. 下一阶段建立人工参考证据集和调试/测试划分，再冻结条件做质量对比。真实QQ阶段依赖用户拥有的应用权限、凭据与HTTPS部署，当前不得填报成功。

## 首次真实调用后的修订设计

基线1bb65a2的实际向量、视觉与四条派生均返回，但三个查证任务都在首次动作失败：模型未经search便编造inspect_image目标，服务端以INVALID_TARGET拒绝。原始记录run-01-baseline.json保留。静态schema允许模型选择尚不可用的工具，短提示未使小模型遵守动作阶段。

修复仅涉及Ollama动作生成接口：由本次观察构造JSON schema，初始仅允许search；获得候选后才允许read_context且target_id限定实际候选消息；读取上下文后才允许inspect_image且限定已读图片；final的引用限定本任务已读观察。提示写清ID类别与图像观察的引用义务。既有Runner资格、目标、额度和发布检查继续独立验证，schema不充当安全边界。模型仍选择查询、读取目标、追加动作和答案内容，不硬编码参考答案。

另外单独探测所装Ollama对qwen3:4b的think=false支持。仅在实际接口支持后关闭思考模式以适配短动作决策；如不支持则保留失败并选择有证据的兼容设置。协议与提示变化提升rules_id版本，避免旧任务在新行为下静默继续；新增生成约束回归后重跑真实链路。不通过延长任务期限或替换答案绕过问题。

第二轮a65ced4已不再编造目标，但反复search后耗尽模型额度，三个任务均limited。候选只含定位信息，重复搜索不会读取原文；进一步限制尚未读取任何上下文而已获得非空候选时只能read_context。取得原文后可继续读取、核图、改写检索或回答；空候选允许改写或声明不足。不要把此生成阶段进度策略替代Runner的安全检查。演示适配器未改变，维持v1身份；只有Ollama适配器升为v2。

第三轮8ab112d会读取原文，但读后仍重复search至limited。对相同已存合成观察作受控探测：原提示再次search；只删除每轮重复的“先search”并明确“已经执行search/read_context”的当前阶段后，模型在同一允许动作schema下正确final；单独只允许final也能正确读取事实。由此在正常请求提示中显式区分首次搜索、已有候选、已有原文三个阶段，保持取得原文后的自主查证选项。探测结果另存planner-state-probes.json，不作为隐藏测试或因果泛化结论。
