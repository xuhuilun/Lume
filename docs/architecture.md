# Lume 首版架构

日期：2026-11-01。用户授权：以QQ为接入示例构建论文系统源码并发布到xuhuilun/Lume，沿既有论文推荐设计持续实施。仓库初始为空；本设计复用论文技术路线，不再重新选择技术栈。

## 最小完整闭环

已授权QQ格式消息/签名事件 → 消息版本及图片 → 后台处理 → 词项与向量候选、RRF → 只读Agent读取上下文/原图 → 引用及来源依赖 → Web工作台核对。先提供无需账号或模型的明确标识演示模式，再提供Ollama真实适配器；演示哈希向量及抽取式回放不作为真实语义/大模型质量证据。

后端Python3.12、FastAPI、SQLAlchemy、PostgreSQL/pgvector。前端React/TypeScript/Vite，采用浅色纸面、深色资料栏和绿色状态强调的查证工作台。命令行初始化数据库、建立随机API令牌和导入合成资料；无默认生产密码。API仅创建任务，独立worker处理资料与查证，HTTP连接结束不影响持久任务。

## 数据与控制

主体、空间及显式读取/维护资格；消息稳定身份、不可变版本、图片；带规则身份的派生表示、处理作业；查证任务、动作账本、观察和答案。首版来源依赖以结构化JSON保存，数据库当前版本及授权为判断依据；不宣称已实现论文全部规范化辅助表或近似索引。

范围为当前读取资格与请求范围交集，管理身份不直接开放所有内容。候选元数据只要送入模型就登记依赖，最终答案并入历史依赖；展示、证据读取和历史回用重新检查。发布结果需匹配运行状态、有效租约及领取代次。取消受理后不登记新模型/工具动作，旧调用结果可丢弃但不能据此断言模型已停止计算。

## QQ边界

实现官方Webhook挑战签名和每次回调Ed25519验签、时间窗、事件去重、预先配置的群白名单。支持GROUP_AT_MESSAGE_CREATE及GROUP_MESSAGE_CREATE格式；全量模式取决于平台实际开启能力。不会把回调接收等同于取得完整历史或所有群成员的读取权限。源群身份与Lume用户资格需管理员明确映射。

本版只读接入和Web查证，不安排向QQ群自动发消息。附件仅允许受控本地上传或明确白名单的HTTPS来源、拒绝重定向并限制字节与解码尺寸；失败保留状态。真实QQ公网回调需要用户的AppID/Secret及HTTPS部署，当前不具备凭据，不伪造线上联调。

## 依赖与验证

新增库均服务于空仓库的明确职责：FastAPI/uvicorn提供API，SQLAlchemy/psycopg/pgvector提供关系及向量访问，httpx提供模型/附件调用，cryptography提供Ed25519，Pillow验证图片，pydantic-settings读取配置；React/Vite/TypeScript提供工作台。pytest/pytest-asyncio/ruff用于必要测试和静态检查。

以隔离的真实PostgreSQL/pgvector验证接入去重、版本失效、范围隔离、融合、引用/传递依赖、取消/过期租约、QQ验签及重放；服务替身验证模型异常，不冒充真实模型质量。2026-11-03新增固定权重的Ollama合成资料联调及浏览器核图记录；真实QQ、独立质量与负载仍单列缺口。

## 模型动作与显式原图要求

Ollama依据当前观察生成动作schema：无候选先search，有非空候选且尚未读原文则read_context；目标只能取当前候选或已读图片，引用只能取已读观察。每轮提示写明已经完成的阶段，避免将首次检索指令误读为重复搜索。此生成辅助不代替Runner的运行时授权、预算和条件发布。

资料处理将OCR及视觉描述写入检索索引；供Ollama回答的消息视图只显示原文与图片身份，不传入这些派生文字或文件处理状态。任务可由用户显式设置require_image，冻结于Task.config；此时尚未核查的已读图片触发受约束inspect_image，正常答案必须引用当前任务的实际图像观察。文件和数据库结构不变。视觉非空返回和来源归属均不证明语义支持性，仍需评价和人工核对。
