# 发布前证据充分性核查

日期：2026-11-05。基线5b83fa4。仅实施已批准的证据充分性改进；不生成PDF、不改论文目录或正文，不运行32题保留集，不引入依赖。

## 设计

正常答案的原文选择后，增加一次与规划分开的Ollama核查，沿用当前chat_model与权重。核查只接收本次问题、require_image以及已选持久原文/实际图像观察，使用服务端短标签S1—S4；不接收题号、参考标签、预期终态或候选排名。

核查固定四维：fact（每个所问字段及测量对象）、unit（单位及可合法换算）、scope（环境/版本/租户边界）、status（建议、执行、验证阶段）。各维给出supported/not_required/unsupported/uncertain和来自所选原文的精确短引文。fact不能not_required；supported必须有逐字存在的引文。过程题需要区分多个阶段，不因包含未执行建议而整题拒绝。图像核查仅能检查观察文字是否覆盖所问字段，不能证明识别文字对应像素。

程序独立检查JSON结构、四维完整性、短标签与精确引文。合法核查若任一适用维度unsupported/uncertain，发布固定“资料不足”；合法全部支持才允许发布原文。格式或引文不合法记录SUPPORT_REVIEW_INVALID并使任务failed，不计作正确拒答。HTTP失败、超时、额度耗尽保留既有failed/limited语义，不混成insufficient。

核查作为support_review动作计入原有12次模型额度；不提高90秒期限、工具8/图像2预算或4096服务上下文。核查前后复核资格、来源版本、范围及领取代次。持久support_review观察记录四维结果、有效性、接受与否和绑定摘要，不能被用作来源引用。摘要绑定问题、核图要求及完整所选来源；publish独立复核记录归属和摘要，规划器不能伪造一个“通过”字段跳过核查。

新任务由服务端冻结answer_contract=reviewed-excerpts-v1，Ollama规则升v5，Demo保留v2与旧回放行为。无数据库列变化，仍用现有Observation/ActionRecord。已有安装需停API/worker、reindex、处理派生后重启。本轮不自动重建原项目数据。

## 实施与验证

1. 先以真实API/数据库/Runner发布复现“问文件上限却仅有分片原文，无独立核查仍可发布”的失败；保留红报告。
2. 实现共享选定原文解析、核查结构/引文/绑定检查、Ollama核查调用及Runner发布门控，补格式、伪造/错配、单位/范围、建议阶段、预算和在途来源失效回归。
3. 使用旧开发运行中的真实问题与所选材料，重放3个反例和若干正例以观察核查能力；这是真实模型开发诊断，不是独立质量评价。保存失败，不按题号或固定答案硬编码。
4. 提交冻结实现后，用同数据/权重完整执行16题开发集，另存逐调用、四维核查、所选来源、终态及失败。更新离线审阅，使“合法核查拒绝”和“核查无效失败”分开。
5. 自检、同步docs、合并main并推送明确授权的Lume仓库，交付outputs中的源码与执行证据。

## 接受与边界

目标是减少已观察的字段缺失、对象/单位混用、环境错配而正常发布。必须同时检查可回答正例，避免全部拒答冒充改进；无法达到的情况如实保留。逐字引文只证明来源绑定，不证明语义支持；同一模型承担规划和核查仍可能共同误判，不能称自动事实验证保证。参考标签依旧pending、人审0，正式质量和负载不在本轮完成范围。

## 真实重放后的收紧

首次8题重放中，部分核查把fact设为not_required，违反程序语义；记录为INVALID_REVIEW_FORMAT，未冒充正确拒答。生成schema现用单独FactFinding类型从结构上禁止该选项。

第二次仍把QA当prod，并在一个可回答正例中将原文字段改写成不存在的引文。现增加两项通用约束：（1）含prod/qa/test/staging/sandbox/integration/dev/uat等独立段的显式连字符环境标识，在所选原文中须按大小写归一、完整词边界出现，否则程序否决支持；不处理别名，不证明存在标识就语义支持。（2）quote从服务端给出的逐字原文片段枚举选择，长文本按句界和最多400字符的重叠窗口构造，仍复核实际子串。没有修改原文来迎合模型。

第三次重放中，3个原始反例被拒绝、4个可回答事实/过程正例通过，另一道缺颜色的视觉观察被拒绝。重放在未提交工作树进行，以实际请求schema和最终content为证据，不声称存在不可变执行提交。后续完整16题实验在提交冻结后独立执行，不覆盖probe-01/02/03。

附加代码审查复现了test-driven、run-integration-tests被误认成环境的反例。已先保存失败用例，再将显式环境格式限定为“名称前缀-阶段[-数字修订]”，阶段不在首段，后缀只接受数字或r/v加数字；这避免当前两个普通术语误拒，也意味着地区后缀、中文环境名或未声明别名不在该字面兜底规则范围。模型语义核查仍负责其余范围约束，不能宣称全面环境识别。
