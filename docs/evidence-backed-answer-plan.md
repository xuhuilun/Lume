## 推荐设计

1. 检索先在当前资格、范围、版本及规则内，检查查询中含分隔符和数字的明确技术标识（例如错误码或环境名）。若有这些标识，两路检索都要求至少一个标识在索引词项中精确出现；多个标识取OR，支持分步检索。无标识时保留原混合检索。这是字面标识启发式，不处理别名，不证明语义相关性；未命中应说明未找到相同标识，不扩大范围猜测。
2. read_context沿明确回复边扩展受控连通上下文，最多12条、最多4跳，保持同空间、有效当前版本；不能越过停用来源，避免跨入无回复关系的旧环境干扰。循环去重，输出截断/歧义标志，所有返回来源进入依赖检查。原父子一层窗口可能漏掉验证结论，扩展后仍不声称获得全部历史。
3. Ollama决策区分answer、insufficient及继续检索/读取/核图。正常answer只选择已读观察中的具体消息或实际图像观察；程序从持久观察提取完整原文生成展示内容，保存原文中的建议、未验证及环境限定。模型不再提供可直接发布的自由数字总结。
4. Task.config冻结answer_contract=source-excerpts-v1；Runner独立检查每个选择的任务归属、消息身份及原文，按实际选择重建citation_ids与答案文本。缺少选择不能发布普通答案；不足动作使用固定缺口说明，模型不在拒答中补造数字。演示模式继续原有抽取行为，不伪装模型判断。

选择来源是否相关、是否足够仍是模型判断，摘录也可能不切题；来自视觉模型的文字仍可能看错像素。新增约束证明来源绑定和原文展示，不宣称自动完成语义支持判定。图像感知改进列为后续阶段，本轮可观察其剩余错误。
