# Lume 原型实现与论文证据独立审校

## 结论与发布边界

Lume已经具有真实源码组成的接入—处理—检索—Agent—答案/证据工作台闭环，不能继续笼统写成“所有模块无源码”。但源码存在、局部测试断言、实际测试输出、浏览器观察及真实QQ/Ollama集成属于不同证据层。当前可将对应论文条目更新为“原型代码存在，验证范围待对照执行记录”，不能把34项计划整体改为通过。

本轮初审发现一项P1前端迟到响应问题及三项P2功能或设计差异，现经修订后的静态复核均已关闭。下文保留初审定位与原因，末尾记录关闭依据。当前授权源码范围内未发现仍需阻断原型源码发布的明确问题；这不是全面安全审计或面向真实敏感资料的生产部署验收。

## 初审问题

### E-01（P1，静态复核已关闭）：旧身份异步结果可写入新身份页面

定位：frontend/src/main.tsx初审159—182行poll，194—211行submit，213—222行loadEvidence，退出处理约367行。

poll末尾的`else if (!disposed) setTasks(await api('/tasks'))`在await前检查disposed，旧账号请求若在退出或新账号登录后返回，仍会把旧任务列表（含问题正文）写入页面。submit在POST返回后无身份代次检查即openTask，退出期间的迟到返回也可能重新写入旧任务。loadEvidence失败分支没有任务身份检查，会清空新任务证据。

建议：为登录/退出维护会话代次，给每次异步操作捕获代次和适用任务；每个await后的状态写入都核对，或同时取消相应请求。退出清空用户资料状态，并使旧登录、提交、轮询、导入、证据请求失效。验收至少覆盖旧列表响应与退出/再次登录交错、旧提交迟到，以及旧证据失败晚于新任务成功。

### E-02（P2，静态复核已关闭）：默认租约条件使任务自然恢复续跑不可达

定位：backend/src/lume/config.py初审31—33、56—57行，api.py create_task绝对期限，agent.py claim约115—127行。

Settings强制lease_seconds大于task_timeout；任务deadline从创建时算起，领取租约从更晚的领取时刻再加lease_seconds。因此旧租约自然到期时，同一任务的绝对期限已经耗尽，claim会直接进入limited，不会在剩余预算内恢复执行。默认90秒任务与120秒租约尤其如此。现有测试手工将lease_until改成过去能验证过期栅栏，不能证明默认配置能自然恢复续跑。

建议：为在线任务采用短于整体期限的租约及受代次约束的续期，或明确首版只支持过期终止、不声称自动续跑恢复。若实现续期，续期和恢复必须继续遵守原绝对期限、累计预算与取消状态，不能通过心跳复活旧代次。

### E-03（P2，静态复核已关闭）：生成模型配置未进入任务冻结身份

定位：backend/src/lume/config.py rules_id，api.py create_task配置字典，agent.py inputs；providers.py OllamaProvider.plan。

rules_id包含provider、embed_model、vision_model、model_revision、OCR语言，但不含chat_model；task.config也没有保存chat_model。仅改变生成模型并重启执行者时，inputs的规则匹配仍可通过，任务实际使用新provider配置，不能声称生成模型与所有运行条件均按任务快照冻结。

建议：将生成模型及影响生成的配置身份纳入独立任务执行身份，冻结或在执行者不匹配时明确失败；资料派生规则身份与生成模型身份可以分开，避免只换生成模型就要求无关资料全部重建。用不同生成配置的任务/执行者建立契约回归。

### E-04（P2，静态复核已关闭）：重新打开同一任务会清空答案而不重新读取

定位：frontend/src/main.tsx openTask与轮询useEffect依赖`[current?.id, token]`。

openTask总会清空答案、证据、事件，但如果点击的历史任务id与当前任务相同，effect依赖未改变，不会重新轮询。已完成任务因此可以变成空答案状态，直到选择其他任务再切回。这也使“再次打开时重新检查答案资格”在该路径上没有发生。

建议：显式刷新代次或统一任务加载函数，让每次打开都进行受控读取；同时遵守E-01的身份/任务迟到保护。

## QQ挑战与真实集成边界

api.qq_webhook在解析op=13及调用key_for(...).sign之前执行qq.authorize_path，要求已配置AppID、Secret及至少32字符的webhook_token，并比对路径凭据与X-Bot-Appid。普通事件另验证原始body签名和时间窗，再通过群空间白名单与QQDelivery去重。当前代码没有公开无凭据的挑战签名入口。

秘密路径本身是签名能力的持有凭据，不能视为普通公开URL。cli.serve明确关闭uvicorn访问日志；反向代理、隧道、监控等外部系统也应避免记录完整路径。应使用独立高熵随机路径凭据，不与QQ Secret复用。源码仅校验长度，不能据此证明实际部署凭据具有足够随机性。

测试源码存在公开向量密钥派生检查、自签body验签/改体拒绝/过期拒绝、挑战秘密路径拒绝、签名事件重放去重。它们不证明真实账号已开启GROUP_MESSAGE_CREATE、真实HTTPS挑战成功、线上重试/附件有效、源权限可靠映射或可以读取历史。当前没有真实QQ、真实Ollama联调证据，本审查也未重查腾讯网页。

## 与论文设计仍不同或未完成的内容

- 身份使用CLI签发的静态Bearer令牌，停用主体后失效；没有auth_session表、会话到期/刷新或服务端退出会话接口。前端退出只清除页面凭据。
- 来源身份首版为space_id+source_id，平台由空间用途隐含；不是论文通用多平台键。接入整个请求共用事务，没有持久ingestion批次对象和逐条独立失败/重试接口；无失败作业单项重试UI。
- 派生主对象每消息/版本/规则只有一份，OCR/描述在ImageAsset字段中；没有论文全部规范化依赖表、独立文件对象、历史派生产物细粒度追溯及孤立文件回收实现。
- 检索使用简单词法切分、PostgreSQL全文与精确余弦排序；没有近似索引容量或召回证据。单路SQL/向量调用失败会使当前工具失败，没有论文所列单路降级候选返回。
- 动作账本保存kind、epoch和state，没有完整工具参数身份、任务内动作序号、与Observation的显式外键；TaskEvent为全局单调id而非独立任务内序号。异常/超时动作可能保留reserved，处置审计尚非完整。
- 答案为文本及整段citation_ids，不是逐断言—引用关系；程序验证引用归属，不评估语义支持。没有自动摘要生成/压缩，前端提交也未提供history_ids的多轮选择入口。
- cli.work串行且优先处理在线任务；没有独立在线/离线池、全局并发额度、单位时间限流或完整性能计量。长期在线排队可能推迟资料处理。
- schema初始化是create_all及初始版本标记，没有后续迁移体系；范围/租约/状态条件部分由程序保证，不等同于论文所有数据库约束已落地。
- 论文API路径、会话机制及批次契约与首版实际/api路由有差异。论文更新应记录实际契约及缺项，不把两者写成完全一致。
