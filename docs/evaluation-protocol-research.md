# 合成参考数据集评测协议研究

核验日期：2026-11-03。本文仅使用公开一手文献和官方工具文档；以下“本项目约定”为据此制定的工程协议，不是文献已验证的实验结论。

## 1. 数据来源与用途声明

本次数据为**助手编写的合成参考数据，全部标签待人工复核**：12 个合成场景、72 条消息、12 张 PNG 夹具图、48 个问题；每个场景包含事实、上下文、视觉和不可回答问题各 1 个。开发集为 4 个场景/16 题，保留集为 8 个场景/32 题。旧演示题 `pool_size`、`E_CONN_42`、`v1.8` 不属于本数据集。

数据说明应记录用途、构成、生成过程、版本、限制和维护责任；这对应 Datasheets 对数据集来源及使用条件透明化的建议。[Datasheets for Datasets，原论文](https://arxiv.org/abs/1803.09010)

本项目约定：记录消息、问题、图像与标签间的稳定 ID；为 PNG 保存生成规则和内容摘要；注明作者、生成日期、合成性质、人工复核状态及修订原因。不得把助手初稿称作“人工标注数据”“外部基准”或“真实企业样本”。不使用租户数据、私人聊天、账号凭据或未经授权的材料。论文可称“用于验证评测流程与典型错误的合成参考集”，不能据此宣称生产性能或真实用户泛化能力。

## 2. 场景分组切分及泄漏边界

scikit-learn 官方指南指出，相关样本形成组时，普通独立同分布假设可能不成立；评估未见组时，应使验证组不出现在配对的训练组中。[scikit-learn：分组交叉验证](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)

本项目约定：以 `scenario_id` 为切分单位，同一场景的 4 个问题及其派生改写不得跨开发集/保留集；固定场景清单并记录版本。提示词、检索权重、阈值及 `k` 只依据开发集选择，冻结后再评估保留集。若因查看保留集错误而修改系统，必须披露该接触并重新建立后续保留数据，不能继续称为首次未调优评估。

保留问题的证据消息和图片进入检索语料，是开放语料检索任务的正常输入；禁止的是把保留问题、参考答案、qrels 等评测标签送入生成上下文或用于调参。分组隔离不能消除共享模板、题目措辞和合成作者偏好的影响；作者已经参与编写全量内容，因此本划分只是**场景隔离的保留集，不是真正盲测**。

## 3. qrels 与检索指标

官方 ir-measures 将 qrels 表示为 `(query_id, doc_id, relevance)`；TREC 文本格式另有 `iteration` 字段。[ir-measures：Qrels formats](https://ir-measur.es/en/latest/getting-started.html#qrels-formats)

本项目以消息 ID 为检索证据单位，草稿二元 `relevance=1` 表示拟定的有效证据，尚待人工复核；多跳问题可以有多个正例。必须说明正例集合是否穷尽、负例与未判断项如何区分。不能仅因消息属于相同场景，就标为所有问题的正例。

设 `Gq` 为问题 q 的正例集合，`Lq[:k]` 为去重后的前 k 条结果。采用以下固定定义，与 ir-measures 的 Recall、RR、nDCG 含义一致；Recall 不能替换为“前 k 中任意命中一次”。[ir-measures：Measures](https://ir-measur.es/en/latest/measures.html)

| 指标 | 本项目固定定义 | 解释边界 |
| --- | --- | --- |
| Recall@k | `|Gq ∩ Lq[:k]| / |Gq|` | 多证据问题只命中一条，不能算完整召回 |
| MRR@k | 首个正例排名 `r≤k` 时为 `1/r`，否则为 0，再对问题取均值 | 不衡量后续证据是否齐全 |
| nDCG@k | `DCG/IDCG`；`DCG=Σ rel_i/log2(i+1)`，IDCG 使用同一 qrels 的理想排序 | 二元标签下衡量证据排序，不能推导答案正确性 |

本项目约定：固定 k、去重方式、同分排序和聚合范围；开发/保留、问题类型分别报告，不混成单个总分。不可回答题没有正例时，上述指标记为 N/A 并排除宏平均，显式报告排除题数。全量可回答题为 36、保留集可回答题为 24；不可回答题分别为 12 和 8。空 qrels 不能被静默计成满分或检索失败。

## 4. 证据与答案应分开评分

HotpotQA 官方评分器分别计算答案 EM/F1、支持事实集合的 EM/precision/recall/F1，再计算联合指标。这提供了“答案正确”和“找到支持事实”应分开观察的直接实例。[HotpotQA 官方评分器](https://github.com/hotpotqa/hotpot/blob/master/hotpot_evaluate_v1.py)

本项目约定：检索指标只比较返回消息 ID 与 qrels。答案评审另看事实值、时间/版本约束、上下文消歧及必要限定是否正确；引用评审另看引用 ID 是否存在、是否包含支持当前陈述的具体内容。**命中一条二元相关证据，不代表该证据支持答案中的每一项 claim**；不能把 qrel 命中自动折算为所有 claim 的语义支持率。未经逐项人工复核或另行验证的语义判定器，只能报告“引用/证据 ID 命中”，不得命名为忠实性、语义正确率或完整证据支撑率。

视觉问题还应标明所需 PNG ID、消息 ID 和图中应核对的字段/区域；“引用了图片所在消息”“OCR 命中”与“看对图片内容”分别记录。若运行记录没有实际传图或图片读取结果，不能据文本摘要命中宣称验证了视觉理解。这是本项目的证据约束，不代表已经实现区域级视觉评分。

## 5. 不可回答题与人工复核

SQuAD 2.0 的原论文要求系统判断段落是否支持答案，并在没有支持时放弃回答；它不能成为强行生成合理猜测的依据。[Know What You Don’t Know: Unanswerable Questions for SQuAD，原论文](https://aclanthology.org/P18-2124/)

本项目约定：“不可回答”仅相对于当前合成语料成立，人工需确认全语料确实缺失所问关键事实，且没有可推导答案。单报不可回答题的正确拒答数/总数，并在可回答题单报错误拒答数/总数；不要用“全部拒答”获得片面好成绩。拒答答案应说明证据不足，不能附带无来源结论。若使用置信度阈值，仅在开发集校准。

人工复核至少确认：问题可理解且答案唯一或允许明确等价答案；qrels 无漏标和错标；图像与文本一致；上下文题确实需要所声明的上下文；不可回答题确实无证据；复核者和日期可追踪。未完成前，本包状态保持 `pending`，不得仅因结构校验通过就改成“已人工验收”。

## 6. 尚未解决的有效性限制

12 个场景数量少、题型由同一生成过程构造、相邻问题相关、图像为受控夹具；场景分组不能证明题目分布覆盖真实工作场景。中文自由生成答案的分词、同义改写、数值单位以及多种可接受证据尚需制定复核规则；直接搬用英文 token F1 可能失真。二元 qrels 也不提供细粒度证据强弱或逐 claim 支持关系。

本文只核验方法来源并提出可复现约定，没有运行模型、检索服务、OCR 或视觉理解实验。后续应把数据结构检查、评分器自检、真实服务执行和人工语义复核分别记录。只有完成实际运行后，才能在注明版本、样本数和复核状态的条件下报告该参考集上的观测结果；不能将理想输出或离线夹具分数当作实际模型结果。
